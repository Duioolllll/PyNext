# 구현 현황과 후속 개발 방향

기준: 패키지 **0.1.0**, 릴리스 태그 **0.1.0v**. 현재는 소규모 웹 프로젝트의 학습·개발·기능 검증에 한정한다. 보안과 장애 대응이 완성되지 않아 공개 운영 서비스나 중요한 데이터를 처리하는 서비스에는 부적합하며, 인터넷에 직접 공개하거나 신뢰할 수 없는 앱을 실행하지 않는다. 소규모라는 표현은 요청량이나 사용자 수에 대한 성능 보장이 아니다. 아래 순서는 권장안이며 일정은 확정되지 않았다.

## 적용 범위 확대 기준

향후 운영에 적용할 수 있도록 사용 환경과 검증 기준을 구체화하고 아래 영역을 개선할 예정이다. 각 항목의 목표 수치와 지원 환경은 실제 사용 사례와 측정 결과를 바탕으로 정하며, 기준을 충족하기 전에는 운영 적합성을 주장하지 않는다.

- **보안:** 연결·요청 제한, WebSocket Origin, 인증·세션과 CSRF의 책임을 명세하고 취약점 및 악성 입력 테스트를 통과한다.
- **장애 복구:** 워커·저장소·네트워크 장애와 재시작을 시험하고, 캐시 일관성과 데이터 쓰기 실패 시 동작을 문서화한다.
- **성능과 용량:** 요청 크기·동시성·워커 수·하드웨어를 명시한 반복 부하 실험으로 지연·오류율·메모리의 지원 기준을 정한다.
- **배포와 운영:** 지원 플랫폼에서 설치·기동·종료, 관측·경보, 패키지 무결성과 보안 업데이트 절차를 검증한다.

구체적인 작업과 완료 기준은 아래 우선순위에 기록하며, 결과에 따라 적용 범위 안내를 갱신한다.

## 구현 현황

| 영역 | 현재 구현 | 현재 제한 |
| --- | --- | --- |
| 라우팅과 렌더링 | 파일 기반 정적·동적·catch-all 라우팅, 중첩 레이아웃, Python 페이지·API, Axum·ASGI, SSR·SSG·ISR | SSG의 비동기 청크는 빌드 시 결합한다. ISR은 최초 생성 응답을 스트리밍하고 완성된 응답만 캐시한다. |
| 클라이언트 | JS/TS island, load·visible·idle·interaction 활성화, 클라이언트 탐색, 제한된 공유 모델 hydration, 실험적 Python DSL | 공유 모델은 element·text·fragment와 문자열 props 중심이다. 일반 이벤트 재생과 전체 라우트 공통 IR은 완성되지 않았다. |
| 캐시 | 프로세스별 메모리와 SQLite·Redis 공유 ISR, 빌드·쿼리별 키, lease·fencing 및 워커 간 무효화 | 공유 저장소 장애 시 로컬 캐시로 대체하므로 즉시 일관성을 보장하지 않는다. SQLite 전체 용량 및 주기적 청소 정책은 없다. |
| HTTP와 보안 기초 | 전역 HTTP 미들웨어, multipart 업로드, SQLite 세션과 세션 기반 CSRF, 인증·권한 검사 연결점, 선택적 공유 요청 제한 | 자격 증명 검증은 앱이 담당한다. 요청 제한은 본문 수신 후 적용되며 완성형 사용자 계정·로그인 시스템은 없다. |
| 실시간·워커 | WebSocket 크기·서브프로토콜 설정, 제한된 큐, 프로세스 내 pub/sub, 공유 리스너 워커와 재시작 | pub/sub은 프로세스 내부에 한정되고 전체 연결 수 상한은 없다. 작업 중 워커가 종료되면 해당 요청은 실패할 수 있다. |
| 개발과 관측 | `pynext init`, 개발 오류 페이지, 네이티브 파일 감시, JS/TS island HMR, 구조화 로그·지표·선택적 OpenTelemetry | HMR은 island 상태 보존을 보장하지 않는다. Rust 빠른 경로부터 외부 서비스까지의 전체 추적은 완성되지 않았다. |
| 배포 | Python 3.13·3.14 패키지, 로컬 이미지 WebP 변환, Linux standalone 디렉터리 | standalone은 단일 실행 파일이 아니며 호환 시스템 라이브러리가 필요하다. 다른 OS의 standalone 패키징은 없다. |

Linux·macOS·Windows에서 Python 3.13·3.14와 Axum·Uvicorn 조합을 CI로 검사한다. 공유 리스너 워커 실행·재시작은 세 OS에서, 신호 기반 수퍼바이저는 Linux·macOS에서 검사한다. 세부 계약과 보안 경계는 [아키텍처 명세](ARCHITECTURE_SPEC.md), 변경 사항은 [릴리스 노트](RELEASE_NOTES_0.1.0.md)를 참고한다.

## 권장 우선순위와 출시 게이트

후속 개발은 보안·네트워크(P0), 신뢰성·분산 운영(P1), 성능·실행 모델(P2), 배포·공급망(P3), 개발자 경험·생태계(P4)로 나눈다. 보안과 기존 기능 검증을 먼저 수행하며, 워크스트림은 의존 관계에 따라 병행할 수 있다.

적용 범위를 넓히기 전 G0 기준선, G1 보안 기초, G2 복구·운영 검증, G3 외부 감사와 공개 운영 후보 게이트를 통과해야 한다. 각 게이트의 노출 범위·완료 기준, 작업별 검증과 미결정 사항은 [프로덕션 전환 로드맵](PRODUCTION_ROADMAP.md)에 정리한다. 이 순서와 게이트는 제안이며 일정·목표 수치 및 공개 여부는 확정되지 않았다.

## 별도 결정이 필요한 범위

Django 통합은 ORM·폼 활용과 ASGI 서브앱 마운트 중 방향 결정을 보류한다. React 및 React Server Components 호환성은 현재 비목표다. [프로덕션 로드맵](PRODUCTION_ROADMAP.md)의 관련 내용은 별도 결정이 필요한 장기 설계 후보이며 현재 지원이나 구현 약속이 아니다.
