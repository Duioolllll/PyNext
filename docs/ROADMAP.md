# 구현 현황과 후속 개발 방향

기준: 패키지 **0.1.0**, 릴리스 태그 **0.1.0v**. 현재는 소규모 웹 프로젝트의 학습·개발·기능 검증에 한정한다. 보안과 장애 대응이 완성되지 않아 공개 운영 서비스나 중요한 데이터를 처리하는 서비스에는 부적합하며, 인터넷에 직접 공개하거나 신뢰할 수 없는 앱을 실행하지 않는다. 소규모라는 표현은 요청량이나 사용자 수에 대한 성능 보장이 아니다. 아래 순서는 권장안이며 일정은 확정되지 않았다.

## 적용 범위 확대 기준

향후 운영에 적용할 수 있도록 사용 환경과 검증 기준을 구체화하고 아래 영역을 개선할 예정이다. 각 항목의 목표 수치와 지원 환경은 실제 사용 사례와 측정 결과를 바탕으로 정하며, 기준을 충족하기 전에는 운영 적합성을 주장하지 않는다.

- **보안:** 연결·요청 제한, WebSocket Origin, 인증·세션과 CSRF의 책임을 명세하고 취약점 및 악성 입력 테스트를 통과한다.
- **장애 복구:** 워커·저장소·네트워크 장애와 재시작을 시험하고, 캐시 일관성과 데이터 쓰기 실패 시 동작을 문서화한다.
- **성능과 용량:** 요청 크기·동시성·워커 수·하드웨어를 명시한 반복 부하 실험으로 지연·오류율·메모리의 지원 기준을 정한다.
- **배포와 운영:** 지원 플랫폼에서 설치·기동·종료, 관측·경보, 패키지 무결성과 보안 업데이트 절차를 검증한다.

구체적인 작업과 완료 기준은 아래 우선순위에 기록하며, 결과에 따라 적용 범위 안내를 갱신한다.

## 권장 우선순위와 출시 게이트

후속 개발은 보안·네트워크(P0), 신뢰성·분산 운영(P1), 성능·실행 모델(P2), 배포·공급망(P3), 개발자 경험·생태계(P4)로 나눈다. 보안과 기존 기능 검증을 먼저 수행하며, 워크스트림은 의존 관계에 따라 병행할 수 있다.

적용 범위를 넓히기 전 G0 기준선, G1 보안 기초, G2 복구·운영 검증, G3 외부 감사와 공개 운영 후보 게이트를 통과해야 한다. 각 게이트의 노출 범위·완료 기준, 작업별 검증과 미결정 사항은 [프로덕션 전환 로드맵](PRODUCTION_ROADMAP.md)에 정리한다. 이 순서와 게이트는 제안이며 일정·목표 수치 및 공개 여부는 확정되지 않았다.

외부 감사(2026-11-09) 당시 판정은 구현 12건·부분 1건·미완료 15건이었다. 이후 정적 CORS·탐색 경합·CSRF·협력적 취소를 보강하고, 프로덕션 모드 반복 측정·컨테이너·SBOM·취약점 CI·공개 타입을 추가했다. 현재 C1·D2·D3는 부분, E5는 구현됨이다. 외부 재감사나 공개 운영 적합성을 뜻하지 않는다. 근거와 남은 범위는 [후속 구현 현황](RUNTIME_HARDENING.md)과 [전체 표](PRODUCTION_ROADMAP.md)를 따른다.

### 1. 연결 수명과 보안

- HTTP·WebSocket 전체 연결 예산과 초과 시 응답을 정의한다. 개발 버전의 WebSocket은 같은 Origin만 기본 허용하며 추가 출처와 Origin 누락은 명시적으로 설정한다. 전역 미들웨어와 `@require_auth`/`@require_permission`도 핸드셰이크 전에 강제된다. 신원 확립(로그인·세션)과 프록시의 전달 헤더 덮어쓰기는 앱·배포의 책임이다.
- 신뢰 프록시 정책을 유지하면서 본문 수신 전 요청 제한을 검토한다. 정적 파일과 캐시 적중 경로도 같은 보안 정책을 따르는지 확인한다.
- 타임아웃이나 연결 해제 후에도 동기 함수와 외부 쓰기가 계속될 수 있다는 계약을 명시하고, upstream 기한·멱등성 및 종료 절차를 정한다.
- 종료 절차(B6, 구현됨): `/healthz`(liveness)·`/readyz`(readiness, 시작 완료 후·드레인 전만 200)를 두며, SIGTERM 시 신규 연결을 중단하고 진행 요청 완료·WebSocket 1001 종료를 `--shutdown-timeout`(기본 30초) 안에 처리하고, SIGHUP은 워커를 한 대씩 교체하는 롤링 재시작을 수행한다.
- **완료 기준:** 제한 초과, 위조된 프록시 헤더와 Origin, 느린 업로드, 연결 해제, 종료 중 요청을 Axum·ASGI에서 자동 검증하고 운영 기본값을 문서화한다. 상태(외부 감사 2026-11-09): A1·A2·A3·A4·A6·A7·B6 구현됨.

### 2. DB·세션·인증 인터페이스

- 개발 중인 SQLAlchemy async 리소스는 SQLite·PostgreSQL 연결·세션·트랜잭션을 제공한다. [DB 연동 안내](DATABASE.md)의 Alembic 절차를 사용해 모델과 마이그레이션을 앱이 관리한다. 더 많은 드라이버와 운영 검증은 별도로 결정한다.
- Redis 세션 저장소가 있다(`RedisSessionStore`, TTL 만료, 버전 fencing, 만료 자동 정리). 남은 것은 인증 제공자와 권한 모델을 연결할 인터페이스를 정의하는 것이다. 상태(외부 감사 2026-11-09): B1 구현됨, 인증 예제(E3) 미완료.
- **완료 기준:** 연결 실패·정리, 롤백, 세션 만료·폐기, 권한 거부와 CSRF 회귀 테스트 및 예제 앱을 제공한다. 자격 증명 검증의 책임 경계도 명시한다.

### 3. 공유 캐시와 실시간 메시징

- SQLite 디스크 사용량 상한·만료 청소·운영 지표를 설계하고, Redis 클러스터 장애·네트워크 분할과 복구 시 일관성 정책을 검증한다. 현재 단일 노드 재시작과 TCP 단절·복구는 시험했으나 클러스터 split-brain은 검증하지 않았다. 공유 저장소 장애 시 동작은 `fail_open`/`fail_closed` 정책으로 정한다(캐시 기본값 `fail_open`으로 로컬 대체, 레이트리미터 기본값 `fail_closed`로 503). 정책별 동작은 테스트와 문서가 일치한다.
- 여러 프로세스·서버의 WebSocket 메시지 전달을 위한 저장소 또는 브로커와 장애 시 동작을 검토한다. 현재 프로세스 내 pub/sub의 동작을 그대로 분산 보장으로 간주하지 않는다.
- **완료 기준:** 다중 프로세스 재생성·무효화, lease 만료·워커 사망, 저장소 장애·복구, 용량 상한 및 메시지 전달 실패를 자동 시험한다. 상태(외부 감사 2026-11-09): B3·C4 미완료.

### 4. 클라이언트 모델과 탐색

- 공유 모델에서 동적 속성·반복·상태 계산과 전체 라우트 IR의 범위 및 버전 계약을 정한다. 서버와 브라우저 출력의 일치·불일치 복구를 검증한다.
- 일반 이벤트 재생과 HMR 상태 보존, 탐색 취소·로그아웃·개인화 캐시를 검토한다. `head`와 CSP를 안전하게 동기화할 수 없는 경우 전체 탐색으로 돌아가는 정책을 정의한다.
- **완료 기준:** 서버·브라우저 출력 비교, 불일치 복구, 탐색 중 취소, 개인정보 혼입 방지와 각 지원 브라우저의 회귀 테스트를 통과한다.

### 5. 관측성·성능·배포

- Rust 빠른 경로에서 Python과 외부 호출까지 추적 연결을 확대하고, exporter 장애 시 큐 상한과 민감정보 제거를 검증한다. upstream별 서킷 브레이커를 별도로 설계한다.
- 동일 조건의 지연·오류율·CPU·메모리 기준선을 마련한 뒤 Rust–Python 버퍼 복사 감소를 검토한다. GIL 해소나 zero-copy를 측정 없이 보장하지 않는다. 현재 C1은 프로덕션 모드 반복 3회·회당 2,000요청·동일 머신의 회귀 기준선을 확보했다. 별도 머신·TLS·장기간 측정은 남아 있으며 C2·C3·C5·C6는 미완료다.
- Linux standalone의 깨끗한 환경 실행과 컨테이너 보안·SBOM을 검증하고, 다른 플랫폼 패키징과 릴리스 산출물 자동 게시를 검토한다. 현재 D2·D3는 부분 구현이다. 비루트·읽기 전용 Docker 실행과 SBOM·취약점 CI를 검증했으며, 서명·재현 빌드·다중 아키텍처·실제 운영 통합은 남아 있다.
- **완료 기준:** 추적·장애·성능 비교 결과와 지원 플랫폼을 공개하고, 패키지 설치·시작·종료를 CI에서 검증한다.


## 별도 결정이 필요한 범위

선택적 Django ORM·폼 연동은 개발 중이며 [사용 안내](DJANGO.md)에 제약을 정리한다. Django ASGI 서브앱 마운트와 Django 템플릿은 범위 밖이다. React 및 React Server Components 호환성은 현재 비목표다. [프로덕션 로드맵](PRODUCTION_ROADMAP.md)의 관련 내용은 별도 결정이 필요한 장기 설계 후보이며 현재 지원이나 구현 약속이 아니다.
