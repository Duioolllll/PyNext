# ADR-0001: TLS 종료는 리버스 프록시에서 수행한다

- 상태: Accepted
- 날짜: 2026-11-08
- 버전: 0.1.0 (`main` d8560f8 기준)

## 배경

PyNext 0.1.0은 평문 HTTP만 제공한다.

- Axum 서버는 HTTP/1.1과 h2c(HTTP/2 사전 지식 모드, 평문)로만 동작한다.
- `crates/pynext-native/Cargo.toml`에 TLS 관련 의존성(`rustls` 등)이 없고,
  `pynext start`/`pynext dev` CLI에도 인증서·TLS 관련 옵션이 없다.
- 따라서 PyNext만으로는 외부 트래픽에 TLS를 제공할 수 없다.
  공개망에 그대로 노출하면 평문 통신이 된다.

프로덕션에서 TLS를 어디서 종료할지 정하지 않으면, 운영자가 각자
다른 가정을 하고 배포하게 된다. 이 ADR은 그 답을 하나로 고정한다.

## 결정

**PyNext는 TLS를 직접 종료하지 않는다. TLS 종료는 리버스 프록시
(또는 로드 밸런서/인그레스)의 책임이며, PyNext 배포에서는
TLS 종료 프록시를 필수로 둔다.**

- 프록시가 클라이언트와 TLS 연결을 맺고, PyNext에는 평문 HTTP로 전달한다.
- PyNext는 기본적으로 루프백(`127.0.0.1`, CLI 기본값)에 바인딩한다.
  프록시와 PyNext 사이의 구간은 신뢰된 사설 네트워크에 둔다.
- 프록시가 붙이는 `X-Forwarded-*` 헤더는 `--trusted-proxy`로 지정한
  피어에서 온 것만 신뢰한다. (프록시 신뢰 모델의 세부 사항은
  해당 기능의 문서와 설정을 따른다.)
- HSTS 같은 TLS 관련 응답 헤더도 프록시에서 설정한다.
  PyNext 자체가 내보내는 보안 헤더의 기본값은 별개로 정의한다.

## 고려한 대안

### (1) `rustls`로 PyNext에 TLS 종료 내장 — 1.0 이후로 미룸

인증서 발급·갱신(ACME 등), 암호 스위트 정책, 인증서 리로드,
TLS 보안 업데이트 대응까지 PyNext가 떠안게 된다. 대부분의 배포
환경(클라우드 로드 밸런서, 인그레스, Caddy/Nginx)이 이미 TLS
종료를 제공하므로, 지금 내장하는 것은 부담 대비 이득이 작다.

### (2) ASGI 서버(예: Uvicorn)의 TLS 옵션에 맡기기 — 지원 경로 아님

ASGI 모드에서는 운영자가 직접 Uvicorn 등에 TLS를 걸 수 있지만,
PyNext CI가 그 경로를 검증하지 않으므로 공식 지원 경로로 삼지 않는다.
운영자가 선택한다면 그 서버의 문서를 따른다.

### (3) 결정을 미루기 — 기각

운영자가 배포 방식을 정하려면 지금 답이 필요하다. 결정을 미루면
프록시 없이 평문으로 노출되는 배포가 생긴다.

## 영향

- 배포 문서와 운영 가이드는 "PyNext 앞에 TLS 종료 프록시를 둔다"를
  전제로 쓴다. 프록시 없이 PyNext를 공개망에 직접 노출하지 않는다.
- 배포 예제(Caddy/Nginx 등)는 프록시가 TLS를 종료하고
  `127.0.0.1:3000`으로 평문 전달하는 형태를 보여준다. 예시:

  ```caddyfile
  # Caddyfile (예시)
  example.com {
      reverse_proxy 127.0.0.1:3000
  }
  ```

  ```nginx
  # nginx (예시)
  server {
      listen 443 ssl;
      server_name example.com;
      # ssl_certificate / ssl_certificate_key 는 운영자가 관리한다.
      location / {
          proxy_pass http://127.0.0.1:3000;
          proxy_set_header X-Forwarded-Proto $scheme;
      }
  }
  ```

  위 스니펫은 형태를 보여주는 예시이며, 인증서 경로는 운영 환경에 맞게
  정한다. `X-Forwarded-Proto`를 비롯한 전달 헤더는 신뢰 프록시에서
  온 것만 유효하므로, 프록시와 PyNext 사이의 `--trusted-proxy` 설정을
  함께 확인한다.
- 벤치마크·부하 측정에서 "TLS 설정"은 프록시의 설정을 기록한다.
  (PyNext 자체에는 TLS 설정이 없다.)

## 재검토 조건

다음 중 하나라도 해당하면 이 결정을 다시 검토하고 새 ADR을 만든다.

- 1.0 출시 범위를 정하면서 프록시 없는 단일 바이너리 배포가 요구될 때.
- 관리형 인증서(자동 발급·갱신)가 필요한 배포 형태가 주력이 될 때.
- 외부 보안 감사에서 프록시 전제 자체가 문제로 지적될 때.
- `rustls` 생태계가 바뀌어 내장 비용이 크게 낮아질 때.

재검토 시에는 (1)안의 인증서 관리·갱신·보안 업데이트 책임 범위를
먼저 정하고, TLS 1.2·1.3, ALPN h2, 인증서 리로드 테스트를
완료 기준으로 삼는다.
