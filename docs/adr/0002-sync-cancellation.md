# ADR-0002: 동기 핸들러의 협력적 취소와 용량 유지

- 상태: Proposed (구현, PR 검토 대상)
- 날짜: 2026-11-09

## 문제

`asyncio.to_thread`의 대기자를 취소해도 이미 실행 중인 Python 스레드는 멈추지
않는다. 504 후 용량을 즉시 반환하면 느린 외부 호출이 누적될 수 있고, 요청이
실패했는데도 쓰기가 실행될 수 있다. 임의의 스레드를 강제로 중단하면 라이브러리·
락·트랜잭션 상태를 손상할 수 있다.

## 결정

스레드를 강제로 종료하지 않는다. 요청에 스레드 안전한 취소 신호와
`check_cancelled()`를 제공하고, 아직 실행 전인 취소 작업은 호출하지 않는다.
진행 중 동기 핸들러·일반 페이지 레이아웃은 기본 32개로 제한하고 실제 완료할 때까지
용량을 점유한다. 용량이 없으면 503을 반환한다. 종료 드레인은 남은 작업을 추적한다.
제한은 프로세스별이며 앱이 직접 생성한 스레드·실행기는 제외한다.

## 결과와 제한

504·연결 해제 뒤 후속 쓰기는 앱이 취소 신호를 확인하고 외부 deadline·트랜잭션·
멱등성을 적용해야 한다. 확인과 쓰기 사이의 취소를 원자적으로 막지는 못한다.
공유 ISR 재생성은 클라이언트 요청과 수명이 달라 독립적으로 완료한다.
종료 유예가 만료되면 프로세스 수퍼바이저의 종료 정책이 적용되며 강제 종료는
진행 중 외부 쓰기를 롤백하지 않는다. 요청별 프로세스 격리는 직렬화·리소스 수명·
취소 비용을 별도로 설계한 뒤 검토한다.
