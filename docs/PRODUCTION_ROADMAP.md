# 프로덕션 전환 로드맵

기준: 0.1.0. 현재 사용 범위는 소규모 웹 프로젝트의 학습·개발·기능 검증이다. 공개 운영 서비스와 중요한 데이터 처리에는 부적합하며 인터넷에 직접 노출하지 않는다. 이 문서는 구현 완료 목록이 아니라 제안과 검증 기준이다. 표 A–E의 상태 열만 2026-11-09 외부 감사 판정을 반영한다. 기능 확대보다 기존 기능의 보안·정확성·장애 동작을 먼저 증명한다.

TLS 종료는 리버스 프록시에서 수행한다. PyNext 자체는 TLS를 종료하지 않는다. ([ADR-0001](adr/0001-tls-termination.md))

첨부된 「PyNext 프로덕션 전환 로드맵」의 다섯 워크스트림과 출시 기준을 반영하되, 현재 코드와 게시 상태에 맞게 정정했다. 원문은 2~3명 기준 9~12개월을 추정했으나 팀 구성·범위·감사 일정이 정해지지 않아 일정 약속으로 사용하지 않는다. 원문의 4개 게이트 상세는 첨부에 포함되지 않아 아래 G0~G3은 이 문서의 제안이다.

## 현재 근거와 제약

- Axum은 HTTP/1.1·h2c를 제공한다. TLS 종료는 리버스 프록시에서 수행한다(ADR-0001). HSTS·X-Frame-Options·Referrer-Policy·Permissions-Policy·확장 CSP를 포함한 보안 헤더가 모든 응답 종류(SSR·SSG·ISR·API·정적·오류)에 적용되며, Rust 빠른 경로에도 적용된다.
- CSRF는 세션 미들웨어 사용 시 상태 변경 API에 자동 적용되며 `csrf_cookie_secure` 기본값은 true다. 세션 없는 double-submit 쿠키는 HMAC으로 서명하고 Origin·Sec-Fetch-Site를 검증한다. 개발 버전의 WebSocket은 기본적으로 같은 Origin만 허용하고, 추가 출처와 Origin 없는 클라이언트는 명시적으로 설정한다. 전역 미들웨어와 `@require_auth`/`@require_permission`도 핸드셰이크 전에 강제되며 거부된 업그레이드는 101 전에 차단된다. 공개된 0.1.0에는 이 검사가 없으며, 신원 확립과 세션 외 자격 증명 방식의 검증은 앱의 책임이다.
- 요청 제한은 IPv6 /64 묶음과 바운드 리더보드·전역 슬라이딩 창으로 키 고갈을 방어한다. 전체 연결 수(기본 1024)·IP별 연결 수(기본 128) 상한과 헤더 읽기 타임아웃·최소 본문 수신 속도가 있다. 동기 핸들러는 시간 초과 뒤에도 계속 실행될 수 있다.
- SQLite·Redis 세션과 SQLite·Redis 공유 ISR이 있다. 세션 만료 정리는 백그라운드에서 자동으로 수행되며 충돌 시 409가 발생한다. 공유 저장소 장애 시 동작은 `fail_open`/`fail_closed` 정책으로 정한다(캐시 기본값 `fail_open`으로 로컬 대체, 레이트리미터 기본값 `fail_closed`로 503). 단일 Redis 재시작·TCP 단절은 시험했지만 클러스터 분할 일관성은 미검증이다.
- 0.1.0의 Linux x86-64 manylinux 2.34+, macOS ARM64, Windows x86-64 휠이 Python 3.13·3.14용으로 PyPI에 게시돼 있다. 해당 휠 설치에는 Rust가 필요 없지만 소스 빌드에는 필요하다. Linux standalone은 호환 라이브러리가 필요한 디렉터리다. Windows 공유 리스너 워커 실행·재시작은 CI에서 검증했고, 신호 기반 수퍼바이저 검사는 Linux·macOS에서 수행한다.
- [기록된 스모크 측정](../benchmarks/results-2026-11-08.json)은 loopback, 1,000건, 동시성 10이라는 제한된 조건이다. 첨부 문서의 Next.js 고부하 비교 수치는 원본 측정 파일과 조건을 확인하지 못했으므로 기준선이나 병목 증거로 채택하지 않는다. 슬롯·대기열 포화에 따른 503 가능성은 가설로 재현한다.
- 비신뢰 코드 격리, 완성형 계정 관리, 공개 운영 보안 감사와 장기 부하·클러스터 장애 검증은 없다. 기존 입력·자원 상한, raw HTML 제한, 개인화 응답의 공유 캐시 우회 및 ISR lease·fencing을 유지한다.

## 외부 감사 판정 (2026-11-09)

표 A–E의 상태 열은 2026-11-09 외부 감사 판정을 반영한다. 상태 값은 `구현됨`·`부분`·`미완료`·`—`이며, `—`는 이번 감사 판정 범위 밖이라는 뜻이다. 판정 28건 중 구현됨 12건, 부분 1건(C1), 미완료 15건이며, 나머지 11건은 판정 범위 밖이다.

- C1 부분: 기록된 베이스라인(`benchmarks/baseline-2026-11-08.json`)은 스모크 실행(시나리오당 50요청·동시성 4·1회 반복·개발 모드·부하 생성기와 서버 동일 머신)이라 기준선으로 사용할 수 없다. 정식 조건은 설정 파일(`benchmarks/baseline-config.json`) 기준 요청 2,000건·반복 3회·프로덕션 모드이며, 별도 부하 생성 머신에서 다시 측정해야 한다. 동일 머신 측정은 회귀 기준선일 뿐 운영 처리량 주장이 되지 않는다.
- ADR은 4건 중 1건만 존재한다(ADR-0001 TLS 종료, 채택). 없는 ADR 3건은 동기 핸들러 격리, 1.0 프론트엔드 범위, 분산 세션·캐시 저장소다.
- A8(외부 감사)이 미완료이므로 G3가 요구하는 외부 감사 증거는 아직 없다.

| G3 공개 운영 후보 | 외부 보안 감사의 High 이상 미해결 0건, SLO·회귀 검증, 장애·정합성 시험, 이미지·SBOM·지원 정책·업그레이드/롤백 증거를 확인한다. | 리버스 프록시 뒤 외부 트래픽 허용 여부를 별도 결정 |

공유 버퍼/memoryview, Arrow, sub-interpreter와 free-threaded CPython은 소유권·수명·확장 모듈 호환성 및 취소 경로를 검증하는 선택지다. zero-copy나 GIL 제거를 약속하지 않는다.

ISR 경로를 명시적으로 무효화할 수 있다. 메모리 백엔드는 프로세스 로컬이며, SQLite·Redis 공유 모드는 정상 상태에서 각 워커의 다음 조회에 무효화가 반영된다. 소유 토큰·만료가 있는 재생성 lease와 버전 fencing으로 단일 생성·오래된 결과 덮어쓰기 방지를 제공한다. 저장소 장애 시 동작은 `fail_open`/`fail_closed` 정책으로 정한다. 캐시 기본값 `fail_open`은 로컬 캐시로 대체하므로 즉시 일관성이 보장되지 않고, `fail_closed`는 503으로 응답한다.

React/RSC 호환성은 현재 및 1.0 계획의 비목표다. 추후 별도 결정 시 Flight·모듈 경계·버전 호환·Suspense 및 보안을 별도 설계하고 검증해야 한다. Django ORM·폼 연동은 개발 중이며, ASGI 서브앱 마운트와 Django 템플릿은 범위 밖이다.

## 의사결정과 첫 작업

TLS 종료는 [ADR-0001](adr/0001-tls-termination.md)의 프록시 필수 결정을 따른다. ADR은 4건 중 1건만 존재한다(ADR-0001, 채택). 동기 핸들러 격리, 1.0 클라이언트 범위, 분산 세션·캐시 저장소는 별도 ADR이 필요하다. 원문의 옵트인 프로세스 풀·JS/TS island·Redis 추천은 확정된 정책이 아니다. 팀 규모, 감사 비용·일정, 파일럿 범위, 지원 Python 버전과 성능 목표도 결정이 필요하다.

우선 현재 문서 불일치와 보안 신고 경로를 조사하고, A1~A4의 위협 모델·회귀 테스트, C1 측정 환경, 이미 제공되는 D1 휠의 검증·미지원 플랫폼 목록을 정리한다. 세션 분산(B1)과 캐시 장애(B3)는 보안 작업과 병행할 수 있다. 제품 기능을 무작정 늘리지 않고 게이트별 증거와 미해결 위험을 갱신한다.
