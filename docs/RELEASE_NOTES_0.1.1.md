# PyNext 0.1.1

이번 릴리스는 PR #17에서 HTTP 제한 판정과 런타임·배포 후속 구현을 통합하고,
이미 main에 병합된 PR #18의 검토 #5 수정 13건을 포함한다.

**소규모 웹·통제된 파일럿에만 적용한다. 현재 공개 프로덕션 적합성은 확보하지
않았으며 구체화·개선이 계속 필요하다.** 전체 방향은 [프로덕션 로드맵](PRODUCTION_ROADMAP.md)에 있다.

## 변경 내용

- 네이티브 HTTP 제한을 본문 수신 전 헤더 단계로 옮겼다. HTTP·WebSocket은
  동시 판정 64개를 공유하고 각 판정은 최대 2초를 기다린다. 토큰이 승인되면
  업로드 중단·413·408·후속 실행 503에도 환급하지 않는다.
- Origin이 있는 Axum 정적·SSG·ISR 응답에 ASGI와 같은 CORS 정책을 적용한다.
  CSRF Origin은 신뢰 프록시로 해석한 스킴·호스트·유효 포트를 비교한다.
- 새 클라이언트 탐색이 이전 fetch를 취소하며 늦은 성공·실패가 최신 화면이나
  브라우저 기록을 덮어쓰지 않도록 차단한다.
- 요청의 협력적 취소 신호와 `check_cancelled()`를 추가했다. 동기 핸들러 용량은
  기본 32개로 실제 종료까지 유지한다. 외부 쓰기에는 별도의 deadline·멱등성이 필요하다.
- 다단계 Docker·비루트·읽기 전용 실행, SBOM과 의존성·이미지 취약점 CI를 추가했다.
  Pillow 13.0.0과 PyO3 0.29.3으로 수정 가능한 보안 권고를 해소했다.
- `.pyi`·`py.typed`를 wheel/sdist에 포함하고 실제 설치 상태에서 mypy·pyright를 검사한다.
- 프로덕션 모드로 84,000요청을 반복 측정해 HTTP 오류 0건을 기록했다. 같은 머신의
  회귀 기준선이며 운영 처리량을 보장하지 않는다. 정적 경로의 p99.9 지연도 원본에 공개한다.

## 업그레이드 시 확인

`pynext-framework==0.1.1`을 사용한다. Python 3.13·3.14가 대상이며 기존 `0.1.0v`
태그를 덮어쓰지 않는다. 이미지 최적화 extra는 Pillow 13을 요구한다. 동기 호출이
용량을 초과하면 `503 Retry-After: 1`을 반환하므로 필요한 경우
`create_app(sync_workers=...)`를 설정하고 외부 서비스 timeout을 함께 검토한다.

HTTP·WebSocket의 Origin·CSRF 및 프록시 정책, 504 이후의 외부 쓰기와 늦은 제한
콜백의 토큰 소비 가능성은 [구현 계약](RUNTIME_HARDENING.md)을 따른다.
배포·검사 범위는 [컨테이너 문서](CONTAINERS.md), 타입 경계는 [타입 문서](TYPING.md),
수치와 원본은 [벤치마크 문서](BENCHMARKING.md)에 정리했다.
