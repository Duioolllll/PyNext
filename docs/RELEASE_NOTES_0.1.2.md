# PyNext 0.1.2

0.1.1 이후 검토 #7의 속도 제한 우회와 참고 사항을 수정하고,
검토 #6의 R1·R4를 보완하는 패치다.

- 커스텀 `is_exempt()`가 `super()`에 위임해도 디코딩된 `?`를 쿼리로
  다시 해석하지 않는다. `/input%3Fother`로 `/input`의 면제 규칙을 우회할 수 없다.
- 인코딩된 헬스 프로브도 동명 정적 파일보다 우선하며 시작 전·시작 후·드레인
  상태의 실제 liveness/readiness를 반환한다.
- 리미터를 켰을 때 정적 빠른 경로를 비활성화하던 잔여 조건을 제거했다.
  헤더 단계에서 허용된 정적 GET·HEAD·304·206은 Rust가 직접 응답하며 단일 과금을 유지한다.
- 취소된 핸들러를 500으로 기록하지 않는다. 연결·태스크 취소는 관측용 499,
  네이티브 처리 기한 초과는 응답과 같은 504로 로그·메트릭에 기록한다.
- `pynext.__version__`과 컴파일된 네이티브 버전을 제공하며, Python·Rust
  워크스페이스·설치된 배포판의 버전을 0.1.2로 맞춘다.

- ASGI HTTP·WebSocket이 앱별 미완료 판정 64개와 판정별 2초 기한을 공유한다.
- 사용자 정의 동기 limiter의 예외 경로 훅·키 계산·판정을 실행기로 보내 이벤트
  루프를 막지 않으며, 정상적인 거부는 429, 포화·기한 초과·오류는 503으로 응답한다.
- 호출자가 취소되거나 기한을 넘겨도 실행 중 콜백의 용량은 실제 종료까지 유지한다.
  실행기 대기 중 취소·만료된 작업은 limiter를 호출하지 않는다.
- 잘못된 ASGI HTTP 경로는 토큰 소비 전에 400으로 거부해 네이티브 동작과 맞춘다.
- 공개 `RateLimiter.is_exempt_path()`의 타입 시그니처를 포함한다.

```bash
pip install pynext-framework==0.1.2
```

기한 초과가 이미 실행한 외부 호출을 중단하거나 소비한 토큰을 환급하는 것은
아니다. 실행 중인 늦은 판정이 토큰을 소비할 수 있으므로 Redis·외부 서비스의
I/O timeout도 설정해야 한다. 호스트 실행기 설정이 실제 동시 실행 수를 결정한다.
전체 요청·서버 종료 기한은 ASGI 호스트가 별도로 관리한다.

구체 계약과 회귀 검사 범위는 [리뷰 #7 수정 기록](REVIEW_7_FIXES.md)과
[ASGI 판정 문서](ASGI_ADMISSION.md)를 따른다.
적용 범위는 계속 **소규모 웹·통제된 파일럿**이다. 공개 프로덕션 적합성은
확보하지 않았으며 [개선 로드맵](PRODUCTION_ROADMAP.md)을 유지한다.
