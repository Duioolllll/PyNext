# 지원 정책

## 지원 버전

PyNext는 실험 단계이며, 보안 수정과 버그 수정은 최신 릴리스에만 적용한다.

| 버전 | 상태 | 비고 |
| --- | --- | --- |
| 0.1.3 | 지원 중 | 현재 릴리스. 보안 수정·버그 수정 대상 |
| 0.1.2 | 지원하지 않음 | 이전 릴리스. 보안 수정·버그 수정은 최신 릴리스에만 적용 |
| 0.1.0보다 이전 버전 | 지원하지 않음 | CHANGELOG에 재구성 스냅샷으로 기록된 0.1.0–0.3.0 포함. 해당 태그가 실제로 그 시점에 게시됐다는 뜻이 아니며, 지원하지 않는다 |

보안 수정은 `SECURITY.md`의 정책을 따른다. 이전 버전에서 발견된
취약점은 최신 버전에서 재현되는 경우에만 수정한다.

## 지원 환경

| 항목 | 지원 범위 |
| --- | --- |
| Python | CPython 3.13·3.14 (`pyproject.toml`의 `requires-python` 기준) |
| 운영체제 | Ubuntu·macOS·Windows 최신 버전 (CI 매트릭스 기준) |
| 배포 모드 | Axum 독립 실행, Uvicorn 위의 ASGI |
| 아키텍처 | x86_64·aarch64 (Linux 휠 기준. 자세한 내용은 릴리스 노트 참고) |

지원 환경 밖(예: Python 3.12 이하, 다른 ASGI 서버, 지원하지 않는 OS)의
문제는 재현이 되더라도 수정이 뒤로 미뤄질 수 있다.

## 릴리스 주기

- 고정된 릴리스 달력은 없다. 실험 단계에서는 `main`에 일관된 변경
  묶음이 쌓이면 메인테이너가 릴리스를 만든다.
- 릴리스는 Git 태그와 PyPI 게시로 한다. 현재 릴리스 태그는
  `v0.1.2`다. 첫 0.1.0 릴리스의 `0.1.0v`와 원격의 오래된 `v0.1.0`은 구분한다. 후자는 다른 과거
  스냅샷이므로 혼동하지 말 것(`docs/RELEASE_PLAN.md` 참고).
- 릴리스 노트와 CHANGELOG에는 변경 사항과 알려진 제한을 함께 적는다.

## 버전 정책

- 0.1.0부터 시맨틱 버저닝을 적용한다.
- **0.x에서는 마이너 버전이 호환성을 깰 수 있다.** 공개 API 변경,
  기본값 변경, 설정 형식 변경은 CHANGELOG에 "호환성 변경"으로
  명시한다.
- 패치 버전은 버그·보안 수정만 포함한다.
- 1.0이 되기 전까지는 안정 API를 약속하지 않는다. 공개 API를 쓰는
  쪽은 릴리스 노트의 호환성 변경 항목을 매번 확인할 것.

## 지원 종료와 업그레이드

- 새 릴리스가 나오면 이전 릴리스의 지원은 끝난다. 보안 수정을 받으려면
  최신 릴리스로 업그레이드한다.
- 업그레이드·롤백 경로는 릴리스 노트에 적는다. 세션·캐시 스키마가
  바뀌는 릴리스는 마이그레이션 방법을 함께 제공한다.
- 지원 종료 예정은 릴리스 노트와 CHANGELOG에 미리 알린다.

## 문의처

- 버그·기능 요청: GitHub Issues (이슈 템플릿 사용)
- 사용법 질문·논의: 이슈에 "질문"으로 올린다. 별도의 토론 포럼은 없다.
- 취약점: 공개 이슈를 쓰지 말고 `SECURITY.md`의 비공개 신고 경로를 쓴다.
- 기여: `CONTRIBUTING.md` 참고
