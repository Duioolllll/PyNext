# Changelog

All versions below are experimental. The v0.1.0–v0.3.0 snapshots were reconstructed from preserved development source distributions when those releases were prepared; they are not claims that the tags were published at those earlier development times. The later malformed-query/JSON fix and timeout documentation/test were backported to the reconstructed snapshots.

## Unreleased

- Route discovery stores project-relative entry, layout, and source paths with `/` separators on every platform, keeping manifest paths and route diagnostics consistent on Windows.
- Session lifetime (S-P1-9): sessions are now bounded twice — an idle timeout (`idle_timeout`, default `max_age`) refreshed while the user is active (rolling re-save at most every `touch_interval` seconds, default 300), and an absolute lifetime (`absolute_max_age`, default 7 days) measured from creation that rotation does not extend. Either deadline turns the next request anonymous and deletes the server entry best-effort. Built-in stores persist `created_at`/`last_seen` and `load` returns a `SessionRecord` (a `(data, csrf, version)` tuple with those timestamps); third-party stores returning a plain 3-tuple get no enforcement.
- Session/CSRF token lifetime (S-P1-21): `SessionMiddleware` `max_age` default is now 43200 seconds (12 hours, was 86400) and at most 30 days (was 1 year); the double-submit CSRF cookie carries `Max-Age=csrf_cookie_max_age` (default 43200) and its signature embeds the issue time, so a stolen cookie value stops validating after that long (previous `"<token>.<HMAC>"` values are rejected). Sensitive actions get purpose-bound single-use tokens (`Session.issue_single_use_token()` / `verify_single_use_token()`, one attempt within 10 minutes by default, hash-stored) and a re-authentication check (`Session.recently_authenticated()`, default 15 minutes, recorded by `rotate_on_login()`).
- Redis `fail_open` revocation (S-P1-20): a delete or rotation that fails during an outage queues the old token hash in `RedisSessionStore.pending_revocations` (bounded, oldest evicted when full) and revokes it as soon as Redis is reachable again — every successful load/save/delete flushes the queue, and `flush_pending_revocations()` drains it explicitly. `delete()` reports `True` when revoked now and `False` when queued, so a logout during an outage is no longer silently mistaken for a confirmed revocation.
- Worker default (C-P0-1): `pynext start` now runs a supervisor with 2 worker processes by default (was a single process); pass `--workers 1` explicitly for the old single-process path. One worker crashing (or a rolling restart) no longer takes the server down.
- Concurrency defaults (C-P0-2): `max_concurrent` is now 128 (was 64) and `acquire_timeout_ms` is now 3000 (was 1000), sized for the shared accept queue of both workers. A request that waits the full acquire timeout is shed with 503 and a `Retry-After` of the timeout in whole seconds, so 3 seconds by default (was 1).
- Rate limiting on by default (H-1): requests are now throttled at 300 per client IP per 60-second window (`--rate-limit 0` opts out). `/healthz` and `/readyz` are exempt, so a load balancer can always probe them.
- CORS credentialed wildcard (S-P1-5): `cors_allowed_origins=["*"]` together with `cors_allow_credentials=True` is rejected with a `ConfigError` at config load. A `SecurityConfig` built directly still answers `Access-Control-Allow-Origin: *` and never echoes the request origin, so no cross-origin page can read a credentialed response (browsers ignore a wildcard on credentialed requests).
- Host validation (S-P1-19): with no explicit `allowed_hosts`, only loopback hosts are accepted (`localhost`, `127.0.0.1`, `::1`); serving on a non-loopback address requires an explicit allowlist.
- Response-header control bytes (S-P1-7): a response header carrying a control byte is dropped at the send point on the ASGI path (the native bridge rejects the whole response with 500 instead), so no CTL byte ever reaches the wire.
- Request-smuggling guard deadline (S-P1-31): the first-header-block hold-back in the smuggling guard is bounded by `header_read_timeout` (default 10 seconds) and fails closed on timeout, so a slow sender can neither hang the connection forever nor bypass the framing scan. Ambiguous framing (both `Content-Length` and `Transfer-Encoding`, chunk trailers) is rejected with 400.
- Admission decision failure fails open (H-2): when no rate-limit/admission decision can be produced (gate full or deadline expired), the request is allowed and counted (`rate_limit.fail_open`) instead of being shed with 503.
- Per-IP execution quota (H-5): at most 16 execution slots per client IP by default (one eighth of the 128-slot pool), so a single IP can no longer take the whole pool with slow requests and 503 every other user.
- Session payload encryption (S-P1-25 / M-16): session payloads can be sealed with AES-256-GCM when an encryption key is configured (`encryption_key` / `PYNEXT_SESSION_KEY`, rotation via `encryption_keys`); the `cryptography` package is available through the `pynext-framework[encryption]` extra. Without a key, payloads are still stored in plaintext (with a one-time warning).

- ISR lifetimes are now three axes: `expire` joins `revalidate` and `stale` as the absolute hard cap measured from generation. After `revalidate` an entry is served stale while one background regeneration runs; after `expire` it is never served again (`expire` must be greater than `revalidate`, `float("inf")` caps at one year). `@page(render="isr", ...)` also accepts a named `cache_life` profile (`default`, `seconds`, `minutes`, `hours`, `days`, `weeks`, `max`, matching Next.js `cacheLife` defaults) via `pynext.CACHE_LIFE_PROFILES`; policies written before `expire` keep their old meaning (`expire = revalidate + stale`). The SQLite backend now measures entry lifetimes and leases on the monotonic clock (wall-clock fallback across reboots) and bounds the table to 10,000 rows, purging expired rows and evicting the oldest on insert.

- Segment config inheritance (Next.js `reduceAppConfig`): layouts can declare an ISR policy with `@layout(revalidate=..., stale=...)`; ISR pages inherit unset values from ancestor layouts and only win with a shorter `revalidate` / smaller `stale`. An ISR page with no `revalidate` anywhere in its layout chain fails at load; a longer page value is overridden with a build-time warning naming both files. Layout policies are recorded in the build manifest (schema version 10), so changing one requires a rebuild.

- Add signal errors for pages (`not_found()`/`forbidden()`/`unauthorized()`/`redirect()` and the `NotFoundError`/`ForbiddenError`/`UnauthorizedError`/`RedirectError` classes): the dispatcher answers with the signal's response and counts it, but writes no error log. Real failures get a stable `sha256(type + message + stack)` digest; the 500 body and the error log line carry the same `request_id` and digest, and `lookup_error(digest)` restores the original error record (type, truncated message, sighting count) from a bounded in-process registry. `pynext_errors_total{route,error_type,digest}` counts errors by type and digest (well-known signal digests as labels; computed digests folded to `digest=""` in Prometheus and kept in the snapshot).
- Replace the L1 `PageCache` O(n) eviction scan with an O(1) doubly-linked-list + hash-map LRU (Next.js `lru-cache.ts` model): entry size is key length + body length, a single item larger than `max_bytes` is refused with a warning, zero-size entries are refused, and capacity evictions can be observed through an `on_evict` hook. Explicit removals and expired-entry drops do not fire the hook. L1 defaults (1024 entries / 32 MiB / 2 MiB body) are unchanged.
- Add conditional middleware scopes (`pynext.scoped`, `MiddlewareScope`, `RouteHas`): a middleware runs only when its `source` path pattern (PyNext route syntax) and its `has`/`missing` conditions (header/query/cookie/host, existence or full-match regex, Next.js `matchHas` semantics) hold. Scopes compile once at registration and invalid patterns fail at startup; source matching is fail-closed against encoded paths, and the WebSocket pre-flight shares the scope.

- On-demand revalidation: `page(tags=...)` declares cache tags, `App.revalidate_tag()` / `Request.revalidate_tag()` invalidate every entry carrying a tag (immediate, or deferred with `expire=` so entries serve stale once first), `revalidate=False` makes an ISR page on-demand-only, and `App.revalidate(path, type="layout")` invalidates every ISR page sharing a layout (`/` and `/index` are aliases for path revalidation). Tag invalidations are recorded as timestamps in the shared backend (SQLite/Redis) so other workers observe them on next lookup, local entries are evicted eagerly (including native fresh hits), and a generation that started before an invalidation is served but never stored. External webhooks can trigger the same invalidations via `POST /_pynext/revalidate` with a Bearer secret (`PYNEXT_REVALIDATE_SECRET` or `create_app(revalidate_secret=...)`); the endpoint answers 404 while no secret is configured.
- Record a deterministic build ID (source-hash prefix, `ad`-free) and an optional deployment ID (`pynext build --deployment-id`, `PYNEXT_DEPLOYMENT_ID`) in the build manifest; serve `X-PyNext-Build-Id` / `X-PyNext-Deployment-Id` on every page, API, static-asset and HTML response (ASGI and native) for skew protection, and print the build identity on the server's first log line. (`.pynext/BUILD_ID` still holds the manifest-integrity seal, not the build ID.)
- ISR responses now carry a policy-based `Cache-Control` header (`public, s-maxage={revalidate}` plus `stale-while-revalidate={stale}` when the SWR window is non-zero), ported from Next.js `getCacheControlHeader`, on the ASGI, streaming and native fresh-hit paths, so a CDN in front of PyNext can serve stale while revalidating. SSG and asset headers are unchanged.
- A failed ISR regeneration now retains the previous entry with the revalidate clamped to 3..30s and the stale window kept at at least 3s (Next.js `retainPreviousCacheEntry`), so the previous body keeps serving while retries breathe instead of every request paying for a slow blocking render after the stale window expires. First-generation failures still surface as 500.
- Allow wildcard patterns in `websocket_allowed_origins` with Next.js Server Actions `allowedOrigins` semantics: `*` matches exactly one DNS label (`https://*.example.com`), `**` — only as the leftmost label — matches one or more leading labels (`https://**.example.com`), scheme and effective port must still match exactly, and patterns matching whole domains such as `https://*.com` are rejected at startup. The default (same-origin only) and the strict CSRF Origin check are unchanged.
- Add a route-specificity comparator (`pynext.sortable_routes`, translated from Next.js `sortable-routes.ts`: static < dynamic < catch-all < optional catch-all, then lexicographic, shorter first) and use it to order the routes in the build manifest. A property test pins the comparator's order equal to the Rust trie's `ordered_routes()` on random route sets, and the ported Next.js sort cases are covered as unit tests.
- Standard middleware results (track D P2-1): a middleware may now state its outcome explicitly with `MiddlewareResult` (`next` / `rewrite` / `redirect` / `response`, plus `rewrite_request()` and `redirect_response()` helpers). Calling `call_next` with a rewritten request is a rewrite: the path is validated with the same `_decode_path` the transports use at the edge, routing is re-evaluated against the rewritten request, rate limiting is decided once on the original path, and at most 5 rewrites run per request (fail-closed 500 after that). Returning a plain `Response` keeps working, and a 3xx response with a `Location` header is still a redirect.
- Split the build into stages (Next.js `experimentalBuildMode` equivalent): `pynext build --only-islands` compiles the island bundles without rendering static pages, and `pynext build --only-static` renders the static pages from an earlier compile without re-running esbuild. A compile-only build reuses earlier static pages while the island digests are unchanged and drops the generate stage once they change; `pynext start` refuses a partial build and names the missing stage. `pynext build --static-only` exports a static-only site (SSG pages, public assets and island bundles as plain files under `.pynext/export`, or `--export-dir`) servable with `python -m http.server` and no PyNext server; apps with dynamic SSR, ISR or API routes are refused rather than silently degraded. This is deliberately not a full `output: export` port.
- Incremental builds: `pynext build` compares source hashes with the previous manifest and re-renders only the static pages whose entry, layouts, or shared imports changed (a changed island or public file re-renders every static page); a missing or corrupt digest file is re-rendered too. The build prints a summary (route counts by render mode, rendered vs reused static pages, island bundle sizes from the esbuild metafile, elapsed time) and writes `.pynext/build-report.json`; `--analyze` lists the largest esbuild inputs per bundle.
- Add `pynext info` / `pynext doctor`: environment diagnostics (PyNext/Python/esbuild versions, native extension, manifest and build-report state, CI detection). `doctor` additionally reports pass/fail checks and exits non-zero when a required component is missing. Build failures now point at `pynext info` for bug-report details.

## 0.1.2 (2026-11-09)

- Bound ASGI HTTP/WebSocket rate-limit decisions with one 64-check gate and a 2-second deadline, retain capacity until running callbacks finish, and discard expired/cancelled executor-queued checks before they can charge tokens. Callback failures and invalid decisions fail closed with 503.
- Validate ASGI HTTP paths before rate limiting so malformed paths return 400 without consuming tokens, matching native admission. Add the public `is_exempt_path()` type signature and real Redis/shared-capacity regression coverage.
- Fix a rate-limit exemption bypass in custom `is_exempt()` hooks delegating to `super()`: a decoded literal `?` stays part of the path, so `/input%3Fother` cannot inherit `/input`'s exemption. Preserve query-aware direct calls and isolate the decoded contract across concurrent callbacks (review #7 B-1).
- Reserve decoded health-probe paths before native static serving, including percent-encoded `/healthz` and `/readyz` aliases, so same-name public assets cannot shadow liveness or readiness (review #7 B-2).
- Keep the native static fast path enabled with a limiter after header-stage admission. Verify GET, HEAD, conditional and range responses bypass Python dispatch while each consumes one token and the next exhausted request returns 429, with memory and Redis limiters.
- Record cancelled handlers as 499 for connection/task cancellation and 504 for a native handler deadline, preserving cancellation propagation and synchronous work capacity instead of counting these as internal errors (review #7 B-3).
- Expose typed `pynext.__version__` from installed distribution metadata, expose the compiled native version, align all workspace crates and Cargo.lock with 0.1.2, and verify version consistency in every isolated wheel smoke check (review #7 A-1/A-2). Remove the empty Unreleased heading (A-3).

## 0.1.1 (2026-11-09)

- Check native HTTP rate limits from headers before body intake and Python execution. Over-limit uploads are rejected before `100 Continue`; HTTP/1.1 connections with unread bodies close, while HTTP/2 keeps other streams available. HTTP and WebSocket checks share a bounded admission budget. Each admitted request consumes one token, including uploads that are later abandoned or rejected by body/execution limits.
- Match built-in rate-limit exemptions against decoded paths without treating an encoded question mark as a query delimiter. Preserve custom `is_exempt` overrides and the query-aware public `is_exempt()` helper.
- Apply one CORS policy to native static/SSG/ISR responses and ASGI, including range, conditional, HEAD and preflight responses.
- Abort superseded client navigation and fence both late successes and failures; cover ignored aborts and browser history in Chromium on Axum and Uvicorn.
- Compare CSRF Origin scheme, canonical host and effective port using the trusted proxy identity; reject duplicate and non-ASCII Origin/Host headers.
- Add cooperative request cancellation and retain bounded synchronous handler capacity until threads actually finish (`sync_workers=32` by default); document the limits for external side effects.
- Record repeated production-build benchmarks, drain server log pipes, and serialize the benchmark fixture's shared SQLite connection after reproducing concurrent cursor corruption.
- Add a multi-stage non-root Docker example, read-only/SIGTERM smoke checks, Python/image SBOMs and Python/npm/Rust/image vulnerability CI. Upgrade Pillow to 13 and PyO3 to the fixed 0.29 series.
- Ship public API stubs and `py.typed` in wheels/sdists; check installed-wheel consumers with mypy and pyright. Implementation details and remaining production gates live in `docs/RUNTIME_HARDENING.md`.
- Reject non-object JSON build manifests with a clear rebuild error, clean up newly created scaffold ancestors on failure, warn when a partial standalone bundle cannot be removed, and include both bounds in non-integer CLI count errors. Align the roadmap audit totals and document DSL runtime non-finite values, best-effort logout, WebSocket pre-flight limits and shared-only invalidation results (review #5 N1–N13).

- Enforce authorization for WebSocket upgrades (review #4 #1, behavior change): the global middleware chain and the handler's `@require_auth`/`@require_permission` policy now run before the handshake completes on both the ASGI and native servers, so a denied upgrade is rejected instead of an accepted socket leaking data. Handlers that need the identity must re-derive it from the socket (for example from a session cookie the middleware validated); the pre-flight `request.state` is not passed to the handler, and a session rotation/invalidation during the pre-flight is not supported because its `set-cookie` would be discarded.
- Fix the rate limiter's new-key window (review #4 #3): an existing key whose bucket was evicted under table pressure is no longer treated as a brand-new key and denied 429 when it returns within the window; the Redis limiter and the in-process limiter share the fix. Add `--rate-limit-ipv6-prefix-len` (default 64) so a deployment can group a whole /48 into one bucket — a /48 holder can otherwise mint 65,536 /64s and fill the new-key window, still denying genuinely brand-new keys until the window slides (evicted existing keys are never denied).
- Standalone builds (review #4 #4): every artifact is validated before the output directory is created, and a failed build removes the partial bundle, so a retry succeeds instead of failing with `FileExistsError` on the stale output.
- Bound the CLI count flags (review #4 #5): `--workers` 1..64, `--max-concurrent`/`--max-waiting`/`--max-connections` 1..1,000,000, `--shutdown-timeout` 0..3600 (and bounds on the other count/timeout flags). Out-of-range values are rejected with a clear CLI error instead of an `OverflowError` traceback or silent resource exhaustion.
- `pynext build` (review #4 #6) now rejects symlinked directories under `app/` (and a symlinked `app/` itself) with a clear error instead of silently skipping the pages inside.
- `optimize_image` (review #4 #7) now validates width/quality and rejects 0/negative/non-integer values instead of raising `ZeroDivisionError` on `width=0`; the HTTP route already guarded this, this is defense in depth.
- Session fixation (review #4 #8): the documented session policy now requires calling `session.rotate_on_login()` after verifying credentials — a documentation-level requirement, not enforced by the framework (the application must call the hook). A request presenting the session cookie name more than once is treated as having no session (fail-closed).
- Session values (review #4 #9) must be JSON-serializable: assigning a non-serializable value now raises `TypeError` naming the key at assignment time instead of failing with a 500 after the handler runs.
- Standalone builds (review #4 #10) now reject top-level symlinked entries in purelib with a clear error instead of silently skipping them; a nested symlink inside a package is dropped with a warning naming the file.
- Standalone bundle creation (review #4 #11) is now deterministic: entries are copied in sorted order, and the installed `pynext` copy is refreshed so files deleted from the source tree no longer linger in the bundle.
- Non-streaming SSG pages (review #4 #12) are now capped at 8 MiB, consistent with the streaming cap (the 30-second limit on SSG and ISR streams pre-existed and is unchanged).
- A streaming static-page build timeout (review #4 #13) is now wrapped as a build error instead of propagating a raw `asyncio.TimeoutError`.
- A corrupt build manifest (review #4 #14) now raises a wrapped build error instead of propagating a raw `JSONDecodeError`/`UnicodeDecodeError`.
- Build output files written by `_atomic_write` (review #4 #15) now use mode 0644 instead of 0600, so they are readable as normal build artifacts.
- `_positive_float` (review #4 #16) now rejects `nan`/`inf` at parse time.
- `pynext init` (review #4 #17) now cleans up the created root/app directories on failure instead of leaving an empty directory behind.
- Correct the rate-limiter precision documentation (review #4 #18): microsecond bucket scores are exact integers (unit in the last place 0.25 µs at the current epoch, exact until 2^53 µs, ~year 2255); ties are possible in principle and are broken deterministically by bucket key, never denying the evicted owner.
- `RedisSessionStore` (review #4 #19) now takes a `failure_policy` (default `fail_closed`): on a Redis outage the request answers 503 (`SessionUnavailable`) instead of silently losing session state; `fail_open` starts a fresh ephemeral session (reads work, nothing persists, and a login cannot complete during the outage because the CSRF token is never stored).
- Document the intended `fail_open` invalidation behavior (review #4 #20): `invalidate()` returns `True` when the local removal succeeded; removal from the shared store is best-effort, and a `True` result does not guarantee the shared entry is gone when the shared store is unreachable.
- WebSocket handshakes (review #4 #21) are now rate-limited like HTTP requests on both servers: each handshake consumes one token from the same per-IP bucket, and an over-limit handshake gets 429 with `Retry-After`. Exempt paths skip the check; a limiter that cannot decide fails closed with 503.
- The client DSL (review #4 #22) now rejects the `Infinity` literal (it previously compiled to floating-point infinity); use a finite number instead.
- Share one CSRF signing key across supervisor workers (finding #23, behavior change): the supervisor generates one key and passes it to every worker, so a cookie issued by one worker verifies on the others. Set it explicitly with `--csrf-signing-key` or `PYNEXT_CSRF_SIGNING_KEY` (raw, `hex:` or `base64:`; at least 16 bytes). An empty `PYNEXT_CSRF_SIGNING_KEY` now raises instead of silently falling back to a per-process key.
- Update the production roadmap checklists (`docs/PRODUCTION_ROADMAP.md`, `docs/ROADMAP.md`) to the 2026-11-09 external-audit verdicts, and fix the manual/wiki statements that contradicted the code (native connection limits exist; distributed rate limiting is implemented via the Redis backend).

- Require a same-origin WebSocket `Origin` by default on ASGI and Axum before accepting the handshake. This changes behavior for non-browser clients that omit `Origin`: opt in with `SecurityConfig(websocket_allow_missing_origin=True)` or `--ws-allow-missing-origin`. Additional exact HTTP(S) origins can be configured with `websocket_allowed_origins` or repeatable `--ws-allowed-origin`; wildcard, `null`, malformed and duplicate origins are rejected. Forwarded host and scheme are honored only for configured trusted proxies. Origin checks do not replace application authentication.
- Add an optional, bounded Django ORM/form resource with lifecycle-managed worker cleanup; Django HTTP apps and templates remain out of scope.
- Serialize overlapping SQLite memory-database sessions and application/database lifecycle transitions, and reopen shared ISR stores after startup failure or shutdown.
- Add an optional SQLAlchemy async `Database` resource for SQLite and PostgreSQL, with lifespan-managed connection pools and explicit session and transaction contexts. Include PostgreSQL integration CI and an Alembic guide.
- Generate health endpoints and server-limit controls in the capability table, and align TLS roadmap wording with ADR-0001.
- Add a Redis session store (`RedisSessionStore`, `pynext-framework[redis]` or `PYNEXT_REDIS_URL`) sharing login, rotation and logout across nodes with TTL expiry and version-fenced writes; the session store interface (load/save/delete) is unchanged so external stores keep working.
- Run expired-session cleanup automatically: `SessionMiddleware` now purges expired sessions in a background task every hour by default (`purge_interval`, `None` disables it, `close()` stops it).
- Add `fail_open` / `fail_closed` failure policies for shared-backend outages (roadmap item B4): the ISR cache defaults to `fail_open` (local fallback, as before) and the Redis rate limiter defaults to `fail_closed` (503, as before); each can be flipped via `ISRCache(..., failure_policy=...)`, `RedisRateLimiter(..., failure_policy=...)`, `create_app(..., cache_failure_policy=...)`, or `--cache-failure-policy` / `--rate-limit-failure-policy`. Under `fail_closed`, an ISR page whose shared store cannot be consulted answers 503, and an invalidation that never reached the shared store raises instead of reporting success. Best-effort cache writes stay best-effort in both policies.
- Add `/healthz` (liveness) and `/readyz` (readiness: 200 only after startup and while not draining) health probes on both the Axum and ASGI servers. They bypass middleware, CORS/CSRF and rate limiting, and a user route or public asset at the same path never shadows them.
- Graceful shutdown (B6): SIGTERM/SIGINT to a single-process server stops advertising readiness, closes live WebSockets with a clean 1001 close, waits out in-flight HTTP requests and streaming bodies for up to `--shutdown-timeout` (default 30s, also bounding the native connection drain), then shuts resources down. The supervisor waits the same budget before SIGKILLing a worker, and SIGHUP performs a rolling restart that replaces workers one at a time — a replacement must report ready before the old worker drains — so a rolling restart under load serves no 5xx.
- Add a reproducible load baseline (`benchmarks/baseline.py`, roadmap C1): fixed scenarios (static, SSG, ISR hit, SSR, JSON API, SQLite DB query, streaming) with repeated measurements, p50/p95/p99/p99.9 latency, error rate, server CPU and sampled peak RSS, and recorded load-generator/server environments for separate-machine runs. The DB-query scenario uses a benchmark-only SQLite fixture app. `benchmarks/baseline-2026-11-08.json` is a same-machine smoke run, not a production claim.
- Report p99.9 latency in `benchmarks/bench.py` percentiles.
- Redesign the overload policy (roadmap C7): make the execution wait queue configurable with `--max-waiting` / `max_waiting` (default `min(--max-concurrent, 64)`; 0 waits for nobody), keep the default policy of bounded wait then 503, and return an accurate `Retry-After` — `ceil(acquire_timeout_ms / 1000)` seconds (at least 1) after a full wait, `1` for a full wait queue. Defaults are unchanged: the old hard-coded `min(max_concurrent, 64)` queue and `Retry-After: 1` at the default 1000 ms timeout behave exactly as before.

## 0.1.0

- Add the A1 default security headers to every response (SSR, SSG, ISR, API, static, client assets, preflight, and error pages) on both the ASGI adapter and the native server, including the Rust fast path for static and fresh ISR responses: HSTS in production only (`max-age=31536000; includeSubDomains`, configurable, omitted in development so `pynext dev` on `http://127.0.0.1` is unaffected), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, and an extended CSP (`script-src 'self'` plus the per-request nonce when enabled, `style-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`). All of them are configurable on `SecurityConfig` (set a field to `None`/`False` to disable that header); an explicitly set response header still wins, and the per-request CSP nonce is preserved. See `security_headers()` and `apply_security_headers()`.
- Bound native-server connections (A4): a total TCP connection cap (default 1024) and a per-IP cap (default 128) enforced at accept time — excess connections are closed before any request is read, and a freed slot admits a new client. Slow request headers and idle keep-alive connections close after the header-read timeout (default 10s, configurable), and request bodies arriving slower than 1024 bytes/second on average after a 2-second grace window are rejected with 408 + `Retry-After: 1`. The limits are settable via `serve()`/`start_native()` and `--max-connections`, `--max-connections-per-ip`, `--header-read-timeout-ms`, `--body-min-rate-bytes-per-sec`; they apply to the native (Axum) server only and are enforced per worker process. h2c connections count toward the caps but have no idle timeout.
- Add Redis ISR storage with expiring leases, fenced writes and cross-worker invalidation; add Redis-backed shared rate limiting, including static and cached responses. Redis cache failures fall back locally; rate-limiter failures return 503.
- Add an ISR query-key allowlist and generation-based invalidation across all query variants and shared-cache workers.
- Stream the first ISR generation while caching only complete responses; allow asynchronous SSG chunks to be consumed during the build.
- Add WebSocket subprotocol negotiation, configurable message limits, bounded native queues and bounded process-local pub/sub.
- Share one listener across worker processes, including dynamically assigned ports retained across restarts; the Windows runtime path still requires CI validation.
- Extend the Python client DSL with short-circuiting chained comparisons and improve collection equality, membership and Unicode string handling.
- Add bounded shared island models for server rendering and browser hydration using the same node tree and string props.
- Replace updated JS/TS island modules in the development browser without a full page reload; reload documents after other source changes.
- Gracefully stop idle HTTP keep-alive connections during native server shutdown while allowing active requests to finish.
- Add a relocatable Linux standalone deployment directory containing the interpreter, installed dependencies and built application; compatible system libraries are still required.

## v0.7.0a1 (superseded plan — shipped in 0.1.0)

The 0.7.0a1 release plan was replaced by the 0.1.0 decision; the items below were merged to `main` and are included in 0.1.0.
